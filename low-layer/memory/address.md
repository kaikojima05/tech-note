## 前提

### メモリ空間（アドレス空間）

メモリ空間は、`あるプロセスから見えるアドレスの集合` のこと。
<br />プロセスから見える各アドレスには、下記との対応関係も一緒に見える。

- どのアドレス範囲が使用できるか
  - その範囲が code（コンパイルされた機械語、実行コードとも言う）なのか stack なのか heap なのか
- 使用できるメモリ範囲が物理メモリやファイルのどこに対応しているか
- read-only か read-write か executable か

## そもそもアドレスとは何か

アドレスとは、メモリ空間の中の位置を表す値の名称。
<br />メモリ空間内の `番地`　とも呼ばれる。

```markdown
仮想アドレス空間※後述
+--------------------------------------------+
| 0x1000 - 0x1fff: code 領域, executable     |
| 0x2000 - 0x2fff: data 領域, read-write     |
| 0x3000 - 0x8fff: stack 領域, read-write    |
| 0x9000 - 0x9fff: heap 領域, read-write     |                          
+--------------------------------------------+
```

アドレスは `16進数` で表現されることが多い。
<br />何故16進数が使用されるかというと2進数（コンピュータ内部では全ての値は2進数で表現される）との相性が良く、かつ短い値で表現できるから。

## 仮想アドレスと物理アドレス

### 仮想アドレス

仮想アドレスは、プロセスから見えるアドレスのこと。
<br />より詳細に言うと、実行中のプログラム（プロセス）からアクセス・使用できるアドレスのことであり、その全ては実際のアドレス（これを物理アドレスという）とは異なる値が割り振られている。
<br />実行中のプログラム（プロセス）から仮想アドレスにアクセスし、読み書きを行うと、OS は MMU（Memory Management Unit※アドレス変換機構）を使用して仮想アドレスを物理アドレスに変換し、実際のメモリにアクセスする。

### 物理アドレス

RAM のこと。
<br />ぶっちゃけ大した説明は必要ない、機能としては大体仮想アドレスと同じ。
